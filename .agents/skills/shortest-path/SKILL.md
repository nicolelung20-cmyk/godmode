# Shortest Path

For every task:
1. Define the actual outcome, not merely the requested mechanism.
2. Inspect existing capabilities, integrations, deployments, and reusable components.
3. Generate the smallest viable paths.
4. Prefer the path with the fewest dependencies, least irreversible change, lowest operational risk, and fastest verification.
5. Reuse before rebuild; configure before code; fix root cause before adding workarounds.
6. Verify the selected path before expanding scope.
7. If blocked, identify the exact capability gap and immediately route to the next independent highest-value path.
8. Do not claim a perfect solution exists; continuously optimize against measured evidence.
